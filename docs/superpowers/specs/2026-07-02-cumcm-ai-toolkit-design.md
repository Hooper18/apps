# 数模国赛（CUMCM）AI 协作工具箱 设计

## 背景与目标

三人团队备战 2026 年全国大学生数学建模竞赛（国赛/CUMCM，预计 9 月开赛，72 小时，中文论文）。团队最初设想产出一个"喂往年金奖论文训练出来的写作 skill"，希望它能自动写出高质量论文。经讨论确认这个设想有两个问题：

1. 论文的核心价值在建模内容本身，不是文字包装。单纯靠语料学习产出一个 skill，解决不了"这道题该怎么建模"这个核心问题。
2. 正式比赛团队计划用 Codex，不是 Claude Code。Claude Skill 包格式在赛时环境里不能直接用，产出物必须工具无关。

调整后的目标：做一个工具无关（Codex/Claude 通用）的备赛工具箱，明确划分"AI 能干什么、人必须干什么"——既要让 AI 充分参与建模和写作（不止管格式），又要有护栏防止 AI 编造内容混进最终论文。

### 背景约束

- 赛事：国赛 CUMCM，预计 2026 年 9 月开赛，72 小时，中文论文
- 团队分工目前模糊，谁顺手谁上，不预设固定的"论文手/建模手/编程手"角色划分
- 备赛时间：约 2 个月（到 2026 年 9 月），预算和精力都比较充裕，可以做"大而全"的工程
- 赛时 AI 工具：Codex（不是 Claude Code）
- 赛时使用方式：只由一人的 agent 会话驱动整个 AI 协作流程，不做三人实时协同；一致性靠共享的静态模板/规范文件解决，不靠多会话协同
- AI 参与深度：不止管格式和代码脚手架，要深度参与建模方案提出和正文起草；但所有定量结论定稿前必须人工核对
- 竞赛期间 AI 工具使用据团队目前了解基本不受限制（需要在临近比赛时以当年最新诚信承诺书为准复核，规则可能逐年变化）
- 往年金奖论文语料可通过公开渠道获取（中国大学生在线官网论文展示区、《数学的实践与认识》期刊/学校知网权限可查部分、GitHub/CSDN 上已整理的 2002–2018 特等奖论文合集、零散年份公开转载），不需要依赖学校图书馆内部数据库这一条路

## 整体架构

新建独立文件夹 `cumcm-toolkit/`（当前工作区内，无需独立仓库/部署，因为没有需要上线的东西）：

```
cumcm-toolkit/
├── corpus/              # 原始语料（金奖论文 PDF/文本）—— gitignore，不进版本库（版权考虑）
├── analysis/            # 对语料的分析产出（结构规律、扣分点、写作规范）—— 进版本库
├── templates/           # 论文结构模板 + LaTeX/Word 模板
├── snippets/            # 建模方法代码脚手架库（Python）
├── checklist/           # 赛时用的合规/规范检查清单（含可执行的自动检查脚本 + 人工核对关卡）
├── notation.md          # 三人共用符号表/命名规范
├── AGENTS.md            # Codex 读取的项目级/赛时指令入口
├── .claude/skills/      # 镜像一份 Claude Skill，备赛期间用 Claude Code 迭代打磨用
└── drills/              # 历年真题模拟演练记录（每次演练暴露的问题和改进）
```

技术栈默认：建模/数据处理用 Python，论文排版默认 **LaTeX**（在国赛官方模板基础上强化图表/公式规范），Word 模板作为备选（如果临场发现 LaTeX 在某个环节不趁手）。

关键决策：**语料原文不进 git**（版权考虑，只本地留存），**分析产出物进 git**（这是自己提炼的规范，是真正的资产）。

## 核心组件

### ① 语料收集与分析（`corpus/` + `analysis/`）

收集范围：中国大学生在线官网历年论文展示区、《数学的实践与认识》期刊（学校知网权限可查部分）、GitHub/CSDN 上 2002–2018 特等奖论文合集、零散年份公开转载。目标是覆盖尽量多年份、尽量多题型（连续型/离散型/评价类/预测类各来几篇）。

分析产出是结构化材料，不是读后感：

- 论文骨架模板（摘要/问题重述/假设/符号说明/模型建立/求解/灵敏度分析/模型评价与推广，每节写什么、大致占比）
- 写作规范清单（时态人称、图表编号规则、公式引用方式、参考文献格式）
- 评委扣分点清单（从多篇论文的共性问题反推，比如摘要写成流水账、假设部分和模型脱节、灵敏度分析走过场）

### ② 模板与规范（`templates/` + `notation.md`）

基于①的分析产出，做成可以直接用的东西：LaTeX 主模板（国赛官方模板基础上强化，统一图表/公式宏包配置）、Word 模板作为备选、三人共用符号表规范（提前统一常见变量名，比如目标函数统一用 `Z`、决策变量统一用 `x_i`，避免合稿时对不上）。

### ③ 代码脚手架库（`snippets/`）

按国赛历年题型覆盖的常见方法建 Python 脚手架：回归/拟合、层次分析法（AHP）、灰色预测、时间序列（ARIMA 等）、图论最短路/网络流、线性/非线性规划、仿真（蒙特卡洛/元胞自动机）、评价类方法（TOPSIS/熵权法）等。每个脚手架配一份"什么时候用/参数怎么调/结果怎么解读/常见坑"的说明——具体这道题用不用得上、怎么用，仍然要建模手判断。

### ④ 赛时使用方式（单人驱动，非三人协同）

不要求三人都各自开 Codex 会话协同。一致性靠共享的静态文件解决，不靠多份 AI 会话协同——`notation.md`/`templates/`/`checklist/` 是普通 markdown/代码文件，建模手和编程手直接打开看/抄，不需要自己也跑一个 agent。真正驱动 agent 的是一个人（谁负责整合谁来，不预设固定角色），这个人的 Codex 会话吃进另外两人的产出（建模思路、代码结果、图表），结合⑥深度参与建模和起草，套模板、跑合规检查、整理成稿。

取舍：牺牲"三人各自加速"的部分收益，换来零协调成本；风险是这一人可能变成瓶颈，用共享静态文件让另外两人不完全依赖这个人也能保持产出一致性，缓解但不能完全消除这个风险（见"边界与风险"）。

### ⑤ Codex/Claude 适配层

`AGENTS.md` 是核心入口，告诉 Codex 仓库里有什么、怎么用（比如"写摘要前先看 templates/abstract-guide.md"、"建模前先看 snippets/ 里有没有匹配的方法"）。备赛期间在 Claude Code 里维护和迭代这份内容，`.claude/skills/` 下镜像一份等价的 skill，方便用 Claude Code 打磨同一套材料。核心内容始终是工具无关的 markdown/Python 文件，`AGENTS.md` 和 `.claude/skills` 只是两层薄适配。

### ⑥ AI 建模方案与正文写作

- 给定赛题/子问题，AI 主动提出**多个候选建模方案**（每个说明：用什么方法、为什么适用、需要什么数据、大概能出什么结果、局限是什么），团队据此快速拍板方向——现场三人干瞪眼讨论怎么建模，是 72 小时里最容易空耗时间的环节，这正是 AI 该发力的地方。
- 方向定了之后，AI 直接参与建模：辅助公式推导、检查建模逻辑自洽、结合③产出可跑代码，而不是给个空模板等人填。
- 正文（模型建立、求解过程、结果分析）**允许 AI 直接起草**，人类在草稿基础上修改，而不是必须从零手写。

**护栏（放进 `checklist/`，是强制步骤而非口头要求）**：AI 起草的所有定量结论——公式、参数、数值结果——定稿前必须过一道**人工核对**关卡。这不是不信任 AI，而是数模论文里一旦有编造的数字/公式没被查出来，代价（被判定学术不端、整篇论文可信度崩掉）远大于省下的时间。

## 验证机制：历年真题模拟演练（`drills/`）

工具箱做完后，找一两道历年真题（题型/难度接近最近几年）跑一次全流程模拟：真实建模、真实用脚手架写代码、真实套模板出一份完整论文，时间压缩到 1-2 天（对标正赛节奏）。目的不是产出能获奖的论文，而是暴露工具箱的问题——模板哪里卡手、脚手架覆盖漏了什么方法、清单漏检了什么硬性要求、⑥的"AI 提方案"环节实际好不好用。每次演练的问题记录到 `drills/`，作为下一轮迭代输入。这一步不能省——没有实战检验的模板和清单，大概率赛时会出现"看着挺好、真用起来各种别扭"的情况。

## 边界与风险

- **不做什么**：不做"一键生成论文"式的全自动化（即最初被否决的"喂语料出完美 skill"设想）；不做三人实时协同的复杂机制。
- **AI 的角色**：深度参与建模方案提出和内容起草（组件⑥），但所有定量结论必须过人工核对关卡，人类负责最终判断和对结果的把关。
- **版权**：语料原文只本地留存，不进 git；仓库里只放自己提炼的分析结论和模板。
- **AI 使用合规**：据团队目前了解，国赛对 AI 工具使用基本不限制，但近年赛事诚信承诺书对 AI 使用有过披露要求，建议临近比赛时以当年最新规则为准复核。
- **单点瓶颈风险**：赛时只有一人驱动 agent 会话，这个人卡住会拖慢整体流程；共享静态模板/清单能让另外两人不完全依赖这个人也保持一致性，但不能完全消除这个风险。

## 开放问题（留给 writing-plans 阶段细化）

- 语料收集的具体渠道优先级和数量目标
- 脚手架库的方法清单是否需要按题型标签做检索/匹配（比如"这题像评价类，看 snippets/topsis"）
- 历年真题模拟演练具体选哪一两道题、什么时候做
- `AGENTS.md` 与 `.claude/skills` 的具体内容结构
