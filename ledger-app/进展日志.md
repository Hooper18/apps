## 2026-11-12 iPhone 适配 + 按 Apple HIG 翻新界面

### 起因
用户换了 iPhone，把 https://ledger.tuchenguang.com 加到主屏幕（standalone PWA）用。截图里两个问题：
1. 首页顶部月份切换栏被状态栏 / 灵动岛盖住（"整体要往下一点"）。
2. 底部导航下面多出一截约 58pt 的灰色空白（"下页面边距"）。

用户要求：修好上下边距；按 Apple 的设计规范翻新成独立 App 的质感；不影响现有功能。
中途补充：Apple 怎么设计 App 要去 Apple 开发者网站查原文，不能凭印象。

### 已查清的原因
1. **顶部**：`Home.tsx` 头部同时写了 `pt-4` 和 `safe-top`。`.safe-top` 定义在 `@layer base`，优先级低于 Tailwind utilities，
   所以 `padding-top` 一直是 16px，`env(safe-area-inset-top)` 从没生效。其它页面的头部根本没写安全区。
2. **底部**：截图量出来导航栏本身 = 64pt + 34pt 安全区，下面还多 58pt 灰色（body 背景色）。58pt ≈ 灵动岛机型的顶部安全区高度。
   这是 WebKit 已知问题：主屏幕 web app 在 `viewport-fit=cover` 下，`100%` / `svh` / `-webkit-fill-available` 等高度会少掉安全区那一截，
   `100vh` 才是整屏高度（WebKit bug 254868，状态 NEW，评论 2 给的办法就是 standalone 下改用 `vh`）。
   本项目 `html/body/#root` 用 `height:100%`、Layout 用 `h-dvh`，正好中招。**这一条是根据 bug 单 + 截图尺寸推断的，没有真机复现条件，改完要用户在手机上确认。**

### 从 Apple 开发者网站读到的 HIG 要点（2026-11-12 读的原文，developer.apple.com/design/human-interface-guidelines）
- Layout：必须尊重安全区；全屏背景图要延伸到工具栏 / 标签栏下面铺满屏幕；控件和内容分层。
- Tab bars：标签栏只做导航、不放操作按钮；iOS 上标签栏是浮在内容上方的 Liquid Glass；要带文字标签。
- Typography：iOS 默认字号 17pt，最小 11pt；文本样式 Large Title 34 / Title1 28 / Title2 22 / Title3 20 / Headline 17 semibold / Body 17 / Callout 16 / Subhead 15 / Footnote 13 / Caption1 12 / Caption2 11；不要用 Light 以下字重。
- Color：同一种颜色不要表示不同含义；分组列表用 systemGroupedBackground 那一套背景层级；文字用 label / secondaryLabel 语义色。
- Materials：Liquid Glass 只用于控件 / 导航层，不要用在内容层，要克制。
- Buttons：点击区域至少 44×44pt；自定义按钮必须有按下状态；一屏 1~2 个突出按钮。
- Accessibility：17pt 及以下文字对比度 4.5:1，18pt 以上或粗体 3:1。
- Sheets：要有 grabber，底部留安全区。

### 方案
1. 视口高度：CSS 变量 `--app-h`，默认 `100dvh`，`display-mode: standalone` 下用 `100vh`；iPhone standalone 再用 JS 按屏幕高度写死像素兜底（`src/lib/viewport.ts`）。
2. 安全区：`--sat` / `--sab` 变量 + `pt-safe-*` / `pb-safe-*` 工具类，所有页面头部和底部都接上；离线横幅出现时由横幅吃掉顶部安全区。
3. 底部导航：改成浮动的玻璃胶囊（4 个导航项），"记一笔"从导航栏里拿出来，做成旁边独立的圆形按钮（HIG：标签栏不放操作）。
4. 设计变量（`tailwind.config.js`）：灰阶换成 iOS 系统灰、字号映射到 HIG 文本样式、圆角加大、去掉卡片阴影。
5. 各页逐个调整头部、列表行、分段控件、按钮点击区域。图表配色和所有数据逻辑不动。

## 2026-11-14（续）底部栏整条消失 —— 排查

### 用户反馈（约 15:40，手机时间 3:40）
上线后首页底部整条栏（4 个标签 + 记一笔圆按钮）不见了。截图在会话里（921×2000）。

### 量截图得到的事实（脚本量像素，不是目测）
- 搜索框（CSS 40px 高）= 95 像素；筛选圆按钮（40px）= 95；类目图标圆（40px）= 96~97。→ **1 CSS px ≈ 2.4 截图像素**。
- 屏幕是 440pt 宽，按 440 算应该是 2.093 像素 / CSS px（40px = 84 像素）。实际大了 1.146 倍。
- 所以这台手机的网页**有约 1.15 倍缩放**：CSS 视口约 384×834，不是 440×956。带副标题的行间距 152 像素 = 63.3 CSS px（代码里是 62+1 分隔线），对得上。
- 缩放从哪来没查清（推断：系统的 Safari「页面缩放 115%」或「放大显示」；**未证实**，不影响修法）。
- 顶部安全区 `env(safe-area-inset-top)` 看起来仍然报 62（月份按钮中心在 83 CSS px ≈ 62+22），没有跟着缩放换算。

### 根因
`src/lib/viewport.ts` 把 `screen.height`（956，设备点）直接当 CSS 像素写进 `--app-h`。
视口有缩放时两个单位不相等：外壳 956 CSS px，屏幕只有约 834 CSS px，外壳比屏幕高 122px。
标签栏是贴外壳底部的 absolute 定位（顶边在 956-82=874），整条落在屏幕外面。
本机预览时视口没有缩放（1:1），所以上一轮测不出来。

### 修法（进行中）
- `--app-h` 不再用 `screen.height` 的绝对值，改成「视口宽度 × 屏幕长宽比」：宽度不受那个 WebKit 高度 bug 影响，长宽比没有单位，缩放多少都成立。
- 加合理性检查：算出来的高度必须落在 `[innerHeight, innerHeight×1.15]` 里，否则不写、交给 CSS 的 100vh。
- `fixed bottom-0` / `fixed inset-0` 的弹层同样受高度 bug 影响（会悬在离底部一截的位置），一并改成按 `--app-h` 定位。
- 关于页加一段诊断信息（视口 / 屏幕 / 安全区 / 外壳高度），以后真机有问题截这一屏就能判断，不用再盲猜。

### 调研结论（网页 + 小红书 / 知乎 / 公众号 / X，来源见本次对话）
