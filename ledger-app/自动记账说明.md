# 自动记账：上线步骤和用法

写于 2026-11-15。设计见仓库根 `docs/superpowers/specs/2026-11-15-ledger-auto-ingest-design.md`，过程见 `进展日志.md`。

## 它做什么

| 支付方式 | 怎么进账本 | 你要做的 |
|---|---|---|
| 微信支付 | 电脑上的同步工具读电脑微信里「微信支付」这一个会话，把新付款发给后端 | 无（电脑要开着并登录微信） |
| Apple Pay | iPhone 的 Shortcuts 在刷卡后把商户和金额发给后端 | 无 |
| Touch 'n Go | iPhone 的 Shortcuts 在收到 TNG 付款通知时把通知原文发给后端 | 无（在 TNG 里扫码付款的场景未测） |

自动记的每一笔先标「待确认」。点开看一眼金额和类目，需要的话 AA，点「确认」后变成「自动」。同一个商户改过一次类目，以后就按你改的归类；没见过的商户先落在「其它」。

## 付款提醒（每记一笔弹一条通知）

App → 设置 → 自动记账 → 付款提醒 → 开启。之后每自动记一笔，这台设备会弹一条系统通知（「已记 CNY 46.35 · 三餐」），点开直接进这一笔的确认页。

- iPhone 上必须是「添加到主屏幕」的 App，并且从主屏幕图标打开后再点开启；Safari 标签页里没有这个能力。
- 第一次开启会弹系统的通知权限框，要点允许。
- 一次同步进来超过 3 笔时合并成一条「自动记了 N 笔」。
- 每台设备各开各的；关闭也在同一个地方。
- **没在真机上验证过。**
- 换了主屏幕图标、删掉重新「添加到主屏幕」后，要重新开一次。

## AA（我垫付，只记我那一份）

记账页 / 确认页金额右边有个「AA」按钮（只有支出有）：点开选几个人，金额变成每人一份，备注里记下「AA 4人 总额 ¥400.00」。再点一次同一个人数取消。朋友转回来的钱不用记。

不是均摊的话，直接把金额改成你出的那部分就行。

微信在境外付款记的是**人民币实扣金额**，令吉标价写在备注里（例：`DEMO CAFE · RM18.90`）。

## 第二批的上线步骤（付款提醒，2026-11-17 已上线）

1. **数据库**：SQL Editor 里执行 `supabase/migrations/004_push_subscriptions.sql`。（已做）
2. **推送密钥**：私钥在本机 `supabase/.temp/vapid-private.json`（不进仓库）。设成后端入口的 secrets：`VAPID_PRIVATE_JWK`（私钥 JWK）、`VAPID_PUBLIC_KEY`（公钥，和 `src/lib/push.ts` 里的一样）。（已做）
3. **重新部署入口**：`npx supabase functions deploy ingest --remote=<项目 ref> --no-verify-jwt`。（已做）
4. **推客户端**，然后在手机上开「付款提醒」。

## 上线（按顺序，只做一次）

顺序不能反：先数据库，再后端入口，最后客户端。

1. **数据库**：Supabase Dashboard → SQL Editor，粘贴执行 `supabase/migrations/003_auto_ingest.sql`。可以重复执行。
2. **后端入口**：在 `ledger-app` 目录下部署 Edge Function，必须关掉 JWT 校验（鉴权靠个人令牌）：

   ```bash
   npx supabase login
   ```

   ```bash
   npx supabase functions deploy ingest --project-ref <项目 ref> --no-verify-jwt
   ```

   项目 ref 是 `.env` 里 `VITE_SUPABASE_URL` 中 `https://` 和 `.supabase.co` 之间的那一段。
3. **客户端**：把代码推上线（沿用进展日志里的办法：临时分支 + cherry-pick，只推记账的提交）。
4. **生成令牌**：App → 设置 → 自动记账 → 生成。令牌只显示一次，电脑和 iPhone 各生成一个，方便以后单独撤销。

## 微信支付：电脑同步工具

位置 `tools/wechat-sync/`，详见那里的 `README.md`。

1. 编辑 `tools/wechat-sync/config.json`，填上 `endpoint`（设置 → 自动记账 页面底部的入口地址）和 `token`。
2. 第一次运行只定起点，之前的付款不入账：

   ```bash
   .venv\Scripts\python -m wxpay_sync.sync
   ```
3. 可选：让它从你过去手记的账里学「商户归哪一类」（不新增流水）：

   ```bash
   .venv\Scripts\python -m wxpay_sync.sync --learn
   ```
4. 以后每次运行都会把新付款发过去。想先看会发什么：

   ```bash
   .venv\Scripts\python -m wxpay_sync.sync --dry-run
   ```
5. 常驻运行：盯着微信的库文件，一有变化就同步，不用等定时。付款后大约几秒到十几秒入账（没有专门测过延迟）。

   ```bash
   .venv\Scripts\python -m wxpay_sync.sync --watch
   ```

   开机自启已装（2026-11-15）：Windows 任务计划里的 `LedgerWechatSync`，登录时用 `pythonw.exe`（没有窗口）启动上面这条命令。电脑关机、睡眠或微信没登录时不会同步，回来后会补上 7 天内的付款。

   - 看它在不在跑：`Get-ScheduledTask -TaskName LedgerWechatSync`，或者看 `sync.log` 最后几行。
   - 卸载：`Unregister-ScheduledTask -TaskName LedgerWechatSync -Confirm:$false`，再在任务管理器里结束命令行带 `wxpay_sync.sync --watch` 的 pythonw 进程。
   - 重启后会不会自己起来还没实测过（只验证了手动触发任务能跑）。

限制：

- 电脑不开机、微信没登录时不会入账，开机后补上。
- 微信大版本升级后可能读不了，工具会明确报错（看 `tools/wechat-sync/sync.log`）。
- 转账不在「微信支付」会话里，现在还记不到（数据在各个聊天里，已确认能读，同步还没写）。
- 红包消息里没有金额，没法自动记。
- 自动扣款（先购后付）和订阅续费现在能记。

## Apple Pay：iPhone Shortcuts

以下步骤按 iOS 27 英文界面写，**没有在真机上验证过**，按钮名字可能略有出入。

1. 打开 **Shortcuts** → 右上角 **+**，在描述框里输入：

   ```
   When I pay with any Wallet card, send a POST request to a URL with a JSON body containing the transaction amount and merchant
   ```
2. 生成后点 **Edit**，检查并补齐：
   - 触发块是 **Wallet**（旧系统叫 Transaction），卡片选你刷的那张或 Any Card；**Automation** 打开，**Notify** 关掉。
   - 动作 **Get Contents of URL**：
     - URL：入口地址
     - Method：`POST`
     - Headers：加一条 `Authorization`，值为 `Bearer ` 加上你的令牌（中间有一个空格）
     - Request Body：`JSON`，三个字段，类型都选 Text：
       - `source` = `applepay`
       - `amount` = 点 Shortcut Input → 选 **Amount**
       - `merchant` = 点 Shortcut Input → 选 **Merchant**
3. 测试只能靠真实刷卡（手动点运行时没有金额和商户）。刷完后：
   - App 首页应该多一笔带「自动」或「待分类」的流水。
   - 没出现的话，看 设置 → 自动记账 里这个令牌的「最近使用」时间有没有更新：更新了说明请求到了后端，没更新说明快捷指令没跑或地址 / 令牌填错。

Wallet 给的金额是文字（如 `RM 12.50`），后端会自己认出币种。

## Touch 'n Go：iPhone Shortcuts（通知触发）

真机看到过两种通知，后端都认：

- 在别的 App 里用 TNG 付款（2026-11-15）：「您已支付了RM金额给商户。」
- 在店里用 TNG 扫商户的 DuitNow 码（2026-11-17）：标题「DuitNow转账成功！」，正文「您已成功转账 RM 金额 给 商户。」。TNG 把这种付款当转账，所以**转给朋友的 DuitNow 转账也会被记成一笔支出**，在确认页改类型或删掉就行。

收到别人转账、充值、积分推广这类通知后端会拒掉。2026-11-16 用户在 iPhone 上按下面的步骤搭好了快捷指令（繁体界面）。

1. **Shortcuts** → **+**，描述框里输入：

   ```
   When I receive a notification from Touch 'n Go eWallet, send a POST request to a URL with a JSON body containing the notification body
   ```
2. 点 **Edit** 检查并补齐：
   - 触发块：App 是 Touch 'n Go eWallet；**Automation** 打开，**Notify** 关掉。
   - 动作 **Get Contents of URL**：URL、Method、Headers 和 Apple Pay 那个一样；Request Body 选 `JSON`，两个字段，类型都选 Text：
     - `source` = `tng`
     - `text` = 点 Shortcut Input → 选 **Body**
3. 不是付款的通知（收款、充值、优惠推送）后端会拒掉，不会入账。

繁体中文系统里的叫法（按苹果繁体界面的惯用译名写的，没对着真机核过）：Shortcuts =「捷徑」，Automation =「自動化」，Get Contents of URL =「取得 URL 內容」，Method =「方法」，Headers =「標頭」，Request Body =「要求內文」，Shortcut Input =「捷徑輸入」。

系统是繁体时，TNG 的通知实际仍是简体（2026-11-17 截图）。后端简繁都认（「给 / 給」「转账 / 轉賬 / 轉帳」），繁体是推的，没见过真实样本。

令牌的「最近使用」只记最后一次：积分推广这类通知也会触发快捷指令（被拒），会把付款那次的时间覆盖掉。

早先在备忘录里建的「Ledger Debug」只是为了看通知里到底有什么字，正式用不需要它。

## 排查

| 现象 | 先看哪里 |
|---|---|
| 设置 → 自动记账 提示读取失败 | 没联网，或 003 迁移没执行 |
| 同步工具报「后端返回 HTTP 401」 | 令牌填错或已被撤销 |
| 同步工具报「解密失败」 | 微信重建了库或升级了，需要重新取密钥 |
| 同一笔记了两次 | 不应该发生（按交易号去重）；Apple Pay 没有交易号，同一笔被快捷指令触发两次才会重复 |
| 类目不对 | 改一次并保存，这个商户以后按你改的来 |
